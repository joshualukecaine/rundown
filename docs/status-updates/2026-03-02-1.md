# Status Updates

## 2026-03-02 — Project kickoff & CLI v1

### What happened
- Running plan needs a full restart after 5+ weeks off sick (late Jan onwards)
- Old workflow (spreadsheets + ICS files) couldn't be managed programmatically
- Decided to build around Intervals.icu API — free, has Garmin sync, good REST API

### What was built
- **API client library** (`src/lib/intervals/`) — TypeScript client for Intervals.icu with full error handling, auth, and date normalisation
- **CLI tool** with three commands:
  - `push-plan` — bulk push a training plan JSON to Intervals.icu (with upsert support)
  - `list` — list planned events grouped by week with distance totals
  - `clear` — delete planned events in a date range
- **12-week restart plan** (`cli/plans/restart-2026.json`) — 36 workouts from Mar 3 to May 24

### Structured workouts
- Discovered Intervals.icu's `description` field is dual-purpose — plain text notes AND structured workout definition
- Step syntax (`- 5m Z2 HR`) gets parsed into guided workout steps that sync to Garmin
- Key gotcha: `Z2` defaults to power zones, must use `Z2 HR` for heart rate targeting
- All 36 workouts updated with structured HR zone descriptions (warm up → intervals/steady → cool down)
- Documented in `docs/knowledge/api.md` and `README.md`

### Tested
- All three CLI commands verified against live Intervals.icu API
- Single event created, listed, and deleted successfully
- Date normalisation fix applied (API requires `T00:00:00` suffix)
- Single test workout pushed (Mar 3, event 96127519) — verified in Intervals.icu UI with correct structured steps, HR zones, and zone distribution chart
- Full 12-week plan (36 workouts) pushed via bulk upsert — all events created successfully, test workout updated in place without duplication
